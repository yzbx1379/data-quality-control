## 2. 数据格式

JSONL，UTF-8 无 BOM，每行一条，结构 `{id, content, meta}`：

* `id`：6 位数字编号（如 `000009`），全局唯一，「仅剔除不重排」。

* `content`：完整正文（Markdown 结构 + 代码片段），图片全部 base64 内嵌（自包含），**长文本无截断**。

* `meta`：

  * 必填 7 字段：`title / url / source_platform / author_or_org / publish_time / content_category / is_original`

  * 条件字段：`primary_languages`（数组，可空）、`related_cves`（数组，可空）

## 3. 采集流程

1. **来源限定**：按规范书 §5.3 权威源名单采集（本批次命中：先知社区、安全客）。
2. **采集方式**：playwright 加载原始页（自动执行 JS 过先知/WAF 反爬挑战 + 滚动全页触发懒加载）→ DOM 转 markdown（代码块取 `<pre>` / 语雀 lake 代码卡片读 CodeMirror `state.doc` 全文，规避虚拟化丢中段）→ 图片 requests 带 UA+Referer 直下转 base64 内嵌。
3. **图片处理**：关键信息图片转文字 `<image_desc>`，一般图片 base64 内嵌保证自包含；data-URI 内联图直接保留。
4. **正文补采**：对图片丢失/代码块缺失条目用 `src/collect/recapture_blog.py` 重建 content（见 `src/` 工具约定）。

## 4. 清洗 / 标注 / 脱敏流程

1. **正文补全**：修复先知 lake 编辑器 4 类结构坑（表格拍平 / 多行代码压行 / 长代码块虚拟化 / data-URI 图丢失）+ 代码围栏动态长度（内容内嵌 \`\`\` 时用 4 反引号，规避提前闭合乱码）。
2. **匿名化 / 去武器化**（规范书 §9.6，博客口径）：

   * 个人隐私 → 小写 `x` 占位（手机号 `133xxxxxx33`、真实邮箱 `xxx@email.com`）

   * 内网 IP / 私有域名 → RFC 测试值（`10.x.x.x`、`example.com`）

   * 活跃 IOC（恶意 URL/IP）→ Defanging（`hxxp://`、`1[.]1[.]1[.]1`）

   * 允许保留恶意软件哈希等静态威胁情报特征

   * **本地/回环地址去武器化（2026-09-03）**：`127.0.0.1` / `0.0.0.0`（PoC 监听/回环）→ `10.x.x.x`；`localhost`（私有域名）→ `example.com`。精确边界正则替换，**保护浏览器版本号**（如 `Chrome/150.0.0.0` 的 `0.0.0.0` 不误伤），仅替换非 base64 文本段，112 张 base64 图数据零改动。
3. **营销内容剔除**：剔除结尾公众号推广 / 二维码等广告营销段（规范书 §5.3 非技术内容 ≤0.5%）。
4. **标注**：`content_category`（漏洞分析/注入/恶意样本/RCE 等）、`primary_languages`、`related_cves`（涉漏洞文章标注 CVE 编号）。

## 5. 安全数据分类说明

本批次 `content_category` 分布：漏洞分析 4 / 注入 3 / 恶意样本 2 / RCE 1。

* **漏洞分析**：漏洞原理 + 复现步骤 + 可复用 POC 的原创实战文。
